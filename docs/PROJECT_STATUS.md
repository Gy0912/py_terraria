## 模块与依赖关系

```
game.py ─┬─ menus.py / save.py
         ├─ world.py ── worldgen.py ── structures.py ── tiles.py, items.py
         ├─ player.py ── physics.py, inventory.py, items.py
         ├─ actions.py ── (world, player, creatures, entities, bosses)
         ├─ creatures.py / bosses.py ── physics.py
         ├─ npc.py / panels.py
         ├─ entities.py ── physics.py
         ├─ render.py / lighting.py / minimap.py ── world.py, textures.py
         └─ inventory.py / healthbar.py / manabar.py / ui.py
```

- **世界数据**：每个 32×32 区块有三层 `bytearray`：方块 id、背景墙 id、液体水位（0–8）。多格物体在 `World.objects`（锚点 → 方块 id）和 `World.obj_cells`（格子 → 锚点）中登记，容器内容存放在 `World.containers`。
- **液体**：采用"活跃格"元胞自动机，每 2 帧最多处理 500 格。相邻区块还没生成时，该格进入等待列表，不会因此触发连锁生成。
- **存档**：只写入 `World.modified` 中的区块；物体、容器、NPC、标记和玩家数据全部写入。读档时用相同种子重新生成世界，再把存档内容覆盖上去。

## 本次修复的问题

1. **岩浆和水不反应**：两种液体水位都很低时，原先只在"向两侧扩散"时检查相遇，所以紧挨着也不会生成黑曜石。现在只要接触就会反应。
2. **NPC 被分配到远处的房子**：入住检查原先会把全世界的床（包括远处建筑里的）都当作候选，还会触发远处区块生成。现在只考虑玩家附近 200 格内、已生成区块里的床，按距离排序，入住时直接把 NPC 传送过去。
3. **史莱姆之王卡进岩石**：在狭窄的地方传送时找不到空位。现在会在玩家周围搜索落脚点；如果实在没有，就暂时穿过地形朝玩家移动。
4. **Boss 掉落物埋在土里**：会穿墙的 Boss 在实心方块内被击杀时，掉落物会卡在方块里。现在生成掉落物时会自动向上挪到空位。

### 手动试玩检查清单

1. 开始游戏 → 世界选择 → 新建世界 → 进入；按 Esc → "保存并返回主菜单" → 再次进入，世界和背包应保持不变。
2. 跳跃约为角色身高的两倍多；在水下待 10 秒以上会开始掉血；碰到岩浆后离开，仍会持续燃烧几秒。
3. 挖开海边或洞穴里的水池，能看到水流下去并铺开。
4. 盖一间房（墙、背景墙、门、火把、床），右键床会显示房屋检测结果；10 秒内向导应该入住。
5. 按 E 打开装备栏，穿上盔甲后角色外观改变，防御数值增加。
6. 夜晚使用可疑眼球召唤血瞳巨眼，底部出现 Boss 血条；击败后打开宝藏袋。

## 已知风险 / 未验证

- 弓箭、法杖、护士治疗、魔镜、自动熔炉的界面操作只做了逻辑层面的测试，没有在真实窗口里点过。
- 液体流动在纯 Python 中按预算逐步推进，大面积排水（比如挖穿海底）会持续好几秒，期间会有持续的 CPU 开销。
- 已探索的区块会一直留在内存里；存档文件大小会随改动过的区块数量增长（没有做长期测量）。
- 史莱姆雨和巨眼自然刷新都是概率事件，冒烟测试是直接触发的，没有验证实际出现的频率是否合适。
- `start_screen.jpg` 含有 Terraria 官方标志，公开发布前需要替换。
