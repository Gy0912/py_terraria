# 游戏设计简报（GAME_DESIGN）

**状态**：创意与流程的**工作文档**，非最终 GDD。未标注为「已决定」的内容均为开放问题。

---

## 1. 产品愿景

打造一款**原创**的 2D 沙盒生存冒险游戏：玩家在世界中探索、改造环境、应对威胁，并通过基地与成长逐步掌握世界规则。开发方式为**小型可玩 Demo 驱动**，从多条玩法方向中筛选可长期维护的机制组合。

**非目标**：复刻任何单一商业游戏的完整体验或使用其受保护素材。

---

## 2. 预期玩家体验

- **探索感**：世界有层次（地表 / 地下 / 特殊层）与可识别的区域差异。
- **掌控感**：通过采集、建造、战斗或环境利用解决问题，而非单一路线。
- **节奏**：短时可玩的循环（10～20 分钟）与长期目标并存；Demo 阶段优先前者。
- **可读性**：2D 俯视角或侧视（**未最终选定**）下，交互与威胁清晰可辨。

---

## 3. 设计原则

1. **Demo 先于体量**：先证明好玩，再扩展内容。
2. **系统可组合**：新机制应能与至少一个已有系统产生交互潜力。
3. **单人可维护**：优先数据驱动与简单 AI，避免过早追求 MMO 级复杂度。
4. **诚实迭代**：试玩不通过则削减或重做，不堆未验证功能。
5. **尊重参考边界**：可从商业游戏**学习问题与结构**；玩法组合与呈现须为本项目原创表述。

---

## 4. 候选玩法支柱

| 支柱 | 方向（候选） | 与当前代码的关系 |
|------|----------------|------------------|
| 探索与世界交互 | 群系、分层世界、可破坏地形 | 已有群系数据与背景；**无**方块交互 |
| 环境机制 | 危险区、视野、天气/毒性等 | **未实现** |
| 战斗与成长 | 武器、敌人、遭遇战 | 空 `creatures.py`；无战斗 |
| 基地与生产 | 建造、合成、简单 NPC/自动化 | 空 `inventory.py` 等 |
| 跨系统交互 | 环境改变战斗、资源解锁建造 | **设计目标**；无实现 |

## 5. 候选创新假设（非最终需求）

以下为我们**希望验证**的方向，需与成熟作品区分表述：

| 假设 | 灵感来源（机制层面，非复制） | 我们的组合 / 变化（提案） |
|------|------------------------------|---------------------------|
| H1 环境作为「谜题资源」 | 沙盒游戏中群系常影响刷怪与资源 | 用**少量明确规则**让环境改变玩家工具选择（如照明/耐热），而非仅换背景 |
| H2 短循环多解法遭遇 | 动作沙盒中 Boss 战 | 小型遭遇设计为「战斗 / 建造掩体 / 引怪入环境」至少两种可行策略 |
| H3 基地是探索的「接口」 | 基地恢复、传送、存储类设计 | 基地升级**解锁探索能力**（如更深分层、更好制图），而非纯数值加成 |
| H4 Demo 链式验收 | 独立游戏早期 Access 模式 | 每个 Milestone Demo 自带**一条可讲述的玩家故事**（5 分钟），用于 Go/No-Go |

## 6. Demo 评估方式

每个玩法 Demo 试玩后记录：

| 维度 | 问题 |
|------|------|
| 乐趣 | 是否想再玩一次？最无聊 30 秒在哪里？ |
| 清晰度 | 是否理解目标与失败原因？ |
| 系统耦合 | 是否出现「只用单系统无脑过关」？ |
| 技术债 | 实现是否可在 Pygame 单人中维护 3 个月以上？ |
| 原创感 | 是否像「我们自己的规则」而非单点仿制？ |

**结果**：保留 / 简化 / 搁置；写入 `docs/PROJECT_STATUS.md` 或独立试玩笔记（未来可加 `docs/playtests/`）。

## 7. 当前设计问题

**已决定（v0.3.0）**：侧视角，16 像素方块（玩家宽 1.5 格）；世界按区块流式生成，并保存相对生成结果的改动。

**未决**：

- 进度结构：技能 / 装备 / 世界解锁的优先级？（目前以装备代际 + Boss 解锁 NPC 为主）
- 叙事：纯涌现叙事还是轻量任务引导？
- 参考项目 `PyRarria-master` 仅作**只读**时，允许借鉴的抽象层级（概念 / API 形状 / 禁止逐行移植）？

## 7.5 已采用的跨作品机制（v0.3.0，待试玩评估）

| 来源 | 机制 | 在本作中的作用 |
|------|------|----------------|
| 我的世界 | 床设置重生点、夜晚睡觉跳过 | 让基地成为"安全锚点"，与 NPC 房屋共用同一张床 |
| 我的世界 | 水桶 / 岩浆桶 | 让液体系统可以操作，用来制造黑曜石（→ 黑曜石护符 → 进入地狱） |
| 星露谷物语 | 出货箱第二天早上结算 | 提供不需要找 NPC 的被动收入，形成"白天采集、夜晚收益"的节奏 |
| 星露谷物语 | 磁力戒指 | 减少拾取的繁琐操作 |
| 自动化游戏 | 自动熔炉 | 最小可用的自动化：矿石放进去自动变成锭，为以后的生产链留出入口 |
| Terraria | NPC 房屋、Boss 宝藏袋、事件触发 Boss | 把建造、战斗、经济三个系统串起来 |

试玩时需要关注：出货箱是否会让商人 NPC 显得多余；自动熔炉是否值得它的造价。

## 8. 竞品调研准备（结果均为 **待调研 pending**）

**说明**：本节仅列出**待查证问题**与对比框架，不构成对任何游戏的完整分析或事实断言。

### 8.1 Terraria（待调研）

**拟调查问题**

- 核心循环：白天/夜晚、风险与回报如何节奏化？
- 挖掘与建造：工具阶、方块类型、物理（液体、重力）如何分层引入？
- 探索：世界生成如何保证「值得走远」？
- 战斗与进度：Boss 门槛、装备代际、职业/构筑边界？
- 哪些系统对「单人 Pygame 可维护」成本最高？

### 8.2 Starbound（待调研）

**拟调查问题**

- 星球/区域切换如何影响资源与生物？
- 任务与探索的耦合方式？
- 多人假设下哪些设计可剥离为单人简化版？

### 8.3 Necesse（待调研）

**拟调查问题**

- 哪些生产链适合做成 Milestone 4 规模 Demo？

### 8.4 Core Keeper（待调研）

**拟调查问题**

- 合作向机制中哪些可改为单人 QoL？
