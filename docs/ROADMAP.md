# 路线图（ROADMAP）

**性质**：Milestone 0 起为工程事实或用户已批准的工作；**Milestone 1 及以后均为提案**，不代表已排期或承诺全部实现。无刚性截止日期。

---

## Milestone 0 — 工程基线

**目的**：可恢复、可追踪、可交接的开发底座。

**可玩交付物**：不要求新玩法；要求文档齐全 + 可重复的手动冒烟步骤。

**验收标准**

- [x] 主项目外部备份可验证（2026-10-26）
- [x] 主项目 `git init` + `.gitignore`（排除缓存，保留 `images/`)
- [x] `README.md`、`AGENTS.md`、`docs/PROJECT_STATUS.md`、`docs/ROADMAP.md`、`docs/GAME_DESIGN.md`
- [ ] 至少一次按 `PROJECT_STATUS.md` 执行的冒烟测试并记录结果（**待用户/后续任务**）

**依赖**：无。

**主要风险**：误以为「已能稳定运行」而未做冒烟。

**非目标**：玩法功能、从参考项目复制代码/资源、打包发布。

---

## Milestone 1 — 最小可玩基础（提案）

**目的**：在**复用现有** `player` / `background` / `world` 的前提下，形成「能看见、能移动、能与世界有最小交互」的切片。

**可玩交付物**：小块可行走区域 + 可见玩家 + 相机 + 少量可破坏/可放置方块（或等价交互）+ 最简单的资源反馈（如拾取计数）。

**验收标准（草案）**

- 玩家稳定渲染；移动与碰撞符合直觉
- 相机跟随；世界坐标与绘制一致
- 至少 1 种资源可通过交互获得并在 UI 或日志中可见
- 手动冒烟步骤写入 `docs/PROJECT_STATUS.md` 或 `docs/MANUAL_TEST.md`

**依赖**：Milestone 0 冒烟；可能对 `World` 存储做**增量**重构（非全盘重写）。

**主要风险**：全图 `biome_map` 阻碍迭代；相机/瓦片坐标混乱。

**非目标**：完整物品系统、多人、存档、全部群系玩法差异。

---

## Milestone 2 — 探索与环境 Demo（提案）

**目的**：小场景证明**不同环境改变玩法**（不仅是换背景图）。

**可玩交付物**：2～3 种可区分环境（如地表森林 / 沙漠高温耗氧 / 地下黑暗视野），玩家需用不同策略通过短关卡或收集目标。

**验收标准（草案）**：每种环境至少 1 条可感知机制 + 1 条玩家对策；5～10 分钟可玩流程。

**依赖**：Milestone 1 的移动、相机、基础瓦片交互。

**主要风险**：机制过多导致 Demo 臃肿；仅视觉换皮无玩法差异。

**非目标**：开放世界尺度、完整事件系统。

---

## Milestone 3 — 战斗与成长 Demo（提案）

**目的**：验证战斗节奏与有限成长是否有趣。

**可玩交付物**：2～3 种武器或攻击方式、2～3 种敌人、1 场小型遭遇（迷你 Boss 或精英战）。

**验收标准（草案）**：战斗可读（反馈、受击、失败/胜利条件清晰）；一次遭遇可在 3～5 分钟内完成。

**依赖**：Milestone 1 移动与碰撞；可选 Milestone 2 环境修饰战斗。

**主要风险**：过早做数值与动画导致工期爆炸。

**非目标**：完整技能树、大量 Boss、联机。

---

## Milestone 4 — 基地与生产 Demo（提案）

**目的**：验证建造、合成与一条简单生产链。

**可玩交付物**：放置工作台或等价物、3～5 条合成配方、一种简单持续产出（或 NPC 辅助一次交易）。

**验收标准（草案）**：玩家能用采集资源完成 1 条「采集 → 加工 → 装备/建造」闭环。

**依赖**：Milestone 1 资源与瓦片；可与 Milestone 3 装备挂钩。

**主要风险**：UI 与物品栏复杂度；与空文件 `inventory.py` 的设计需先定稿。

**非目标**：大型自动化工厂、复杂 NPC AI。

---

## Milestone 5 — 跨系统玩法 Demo（提案）

**目的**：验证「多系统组合」是否产生涌现玩法。

**可玩交付物**：单个小场景（例如：特定环境削弱敌人 + 采集物升级装备 + 临时基地抵御一波敌人）。

**验收标准（草案）**：至少 2 个系统相互影响；玩家有 2 种以上可行策略完成目标。

**依赖**：Milestone 2～4 中**已验证有趣**的机制子集。

**主要风险**：强行拼凑未打磨的系统。

**非目标**：内容量接近正式游戏章节。

---

## Milestone 6 — 评估与长期扩展（提案）

**目的**：根据实机试玩决定保留、简化或丢弃的机制；更新路线图与设计文档。

**可玩交付物**：试玩笔记 + 修订后的 `ROADMAP.md` / `GAME_DESIGN.md` + 下一周期 1～2 个聚焦里程碑。

**验收标准（草案）**：每条保留机制有「好玩 / 可维护」理由；废弃机制明确记录原因。

**依赖**：至少完成 1 个 Milestone 2～5 的 Demo。

**主要风险**：无试玩数据仍继续堆功能。

**非目标**：承诺完整发售功能列表。
